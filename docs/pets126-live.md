# Live companion collection and luxury back office

The ten approved pets now live in the game's pet window. Players can inspect all ten, summon once or ten times, equip one companion, upgrade its stars with duplicates, manually cast its skill, and toggle pet skills during AUTO. Premium companions take precedence over the legacy follower; the legacy pet and its intimacy are retained. Flying companions hover above the owner's ground height; ground companions follow at foot level. These use the approved single-view images with follow/bob motion, not a newly authored multi-frame gait or wing cycle.

No payment or top-up endpoint is enabled. Each character's live Khwan Gem balance starts at zero. Preview gems, grants and collections are never imported. Authorized admins can grant gems or one pet/copy in the players page, for online or offline characters. Existing draft rates remain S 3% / A 17% / B 80%, price 100 gems, S guarantee by pull 80, and duplicate costs 1/2/3/4 through five stars. These values can still be tuned before a paid launch.

`pet-account.js` stores wallet, pity, collection, equipped pet, AUTO preference, a global wall-clock skill cooldown and the last 32 mutation receipts. The host uses cryptographic randomness and stages a mutation through the character's save queue. It acknowledges only after a durable lease-checked checkpoint. A repeated request ID returns its receipt without another debit, roll or upgrade; reusing an ID for different arguments is refused. Collection mutation blocks pet AUTO casts while saving, so an in-flight cast cannot overwrite its cooldown. Save failures close the session and drop the stale in-memory peer without checkpointing it over an uncertain write; reconnect reloads the durable profile/receipt. No staged wallet is published to clients. Grants use the existing verified admin and allowed-origin checks; the game socket does not accept grant commands.

The Firebase adapter discards any premium wallet in the first legacy/client-mirror import and strips the new field from every mirror checkpoint. The authoritative collection stays in the private server profile and is sent only to its owner and authenticated admins. Other players see only the active pet's appearance ID. Existing items, class stats, XP and legacy pets are preserved.

Ten abilities affect real monster combat: area damage, heal/poison cleanse, shield/attack blessing, damage reduction, armor reduction, root, heal, shield, mana restoration and slow. Attacks require a visible live monster within nine units and refuse safe towns and PvP proxies. Bosses resist roots and receive the existing reduced slow. Damage uses the normal kill/reward contribution path. Class shields and pet shields keep separate state. Both manual and automatic casts share the persisted cooldown; changing pets does not reset it. Existing bounded class-effect assets provide the visual cast effects.

The admin and dashboard use `backoffice-luxury.css`, matching the landing page's self-hosted Mali, deep jade, parchment and matte gold. Both have illustrated entry gates and cinematic headers, with responsive controls and scrollable data tables. Authentication, balance editing, player gifts, server monitoring and the existing local cost ledger retain their behavior. Existing obscured admin/dashboard URLs remain unchanged; the generic admin.html and dashboard.html redirects remain unchanged.

Validation: all 463 Node tests passed. Unit/integration tests include live abilities, star costs and replay receipts, server-owned balance updates, admin grant authorization, and rejection of forged client-mirror wallets. `scripts/check-pets126.mjs` runs a real local host and Playwright browser, exercises summon/equip/upgrade/skill/admin grant, checks durable saves, and captures the pet panel, admin gate/editor and live dashboard at 1440×900, 844×390 and 390×844. Its Firebase sign-in fixture exists only inside that test browser and never changes production authentication. QA screenshots are local under outputs/pets126.
