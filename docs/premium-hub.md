# กาชา ร้านค้า และสัตว์เลี้ยง

## เมนูในเกม

- กาชา: เลือกพระเครื่องหรือสัตว์เลี้ยง ใช้ทองแท่งกระเป๋าเดียวกัน แต่สะสมการันตีแยกกัน
- สัตว์เลี้ยง: แสดงเฉพาะตัวที่มี จัดการติดตาม อัปดาว และใช้สกิล ไม่มีปุ่มสุ่มในหน้านี้
- ร้านค้า: เลือกสินค้า จำนวนชุด และตรวจยอดรวมก่อนยืนยัน ของเข้ากระเป๋าตัวละครที่ซื้อ
- ปุ่ม “คู่ขวัญของฉัน” ถูกนำออกจากหน้ากาชาตามที่ขอ เข้าจัดการผ่านเมนูสัตว์เลี้ยง
- ปุ่ม ? เปิดคำอธิบายเรททั้งสองตู้ แสดงรางวัลปกติครบทุกชิ้น เรทเฉพาะครั้งการันตี ค่าใช้จ่าย ตัวนับปัจจุบัน ของซ้ำ และกติกาสุ่ม 10 ครั้ง อ่านข้อมูลจากโมดูลกติกาเดียวกับเกม

## สินค้ารอบแรก

| SKU | ของต่อชุด | ทองแท่งต่อชุด |
| --- | --- | ---: |
| rename-card | บัตรเปลี่ยนชื่อ 1 ใบ | 1,000 |
| lek-lai-pack | เหล็กไหล 5 ชิ้น | 100 |
| break-guard | ยันต์กันแตก 1 ชิ้น | 100 |

ราคาเหล็กไหลและยันต์เป็นราคาทดลอง บัตรเปลี่ยนชื่อใช้ราคาเดียวกับระบบเดิม ไม่มีอัตราแลกเงินบาทหรือการรับชำระเงินจริงเพิ่มเข้ามา ซื้อได้ครั้งละ 1–20 ชุด สินค้าทั้งหมดใช้ไอเท็มที่มีผลจริงในเกมอยู่แล้ว

## การบันทึก

`premiumBuy` ส่งเพียง SKU จำนวนชุด และ request ID เซิร์ฟเวอร์อ่านราคาและไอเท็มจาก `premium-shop-catalog.js` เท่านั้น ตรวจทองและพื้นที่กระเป๋า แล้วบันทึกของ ทอง และใบเสร็จพร้อมกันก่อนส่ง `shopChanged` กลับ ไม่ยอมรับราคา/รางวัลจากไคลเอนต์

ใบเสร็จล่าสุด 64 รายการอยู่ในสถานะส่วนตัวของตัวละคร ไม่ส่งออกทาง public wallet คำขอเดิมเล่นซ้ำได้โดยไม่หักเงินเพิ่ม เปลี่ยนสินค้าหรือจำนวนโดยใช้ ID เดิมจะถูกปฏิเสธ เมื่อยังไม่ทราบผลจากเครือข่าย หน้าร้านเก็บ ID เดิมและล็อกจำนวนเพื่อให้ตรวจสอบรายการเดิมก่อนซื้อครั้งใหม่

## ภาพและแอนิเมชัน

ภาพใหม่สร้างด้วย built-in ImageGen เก็บ PNG ต้นฉบับและ prompt ทุกภาพไว้ใน:

- `assets/premium-ui/`: ไอคอนกาชา ร้านค้า กรอบหน้าต่าง ปุ่มหยก/ทอง ปิดหน้าต่าง และภาพหัวข้อ 2 หมวด
- `assets/gacha-neutral/`: ผนึกปิด ผนึกคลาย พลังงานเหนือแท่น และปุ่ม ? โดยไม่มีรูปพระหรือรางวัลชนิดใดในภาพพิธี
- `assets/amulet-ritual-v2/flash.webp`: ภาพแสงว้าบที่ใช้ร่วมในพิธี ส่วน PNG ท่าเดิมเก็บไว้เป็นต้นฉบับแต่ไม่ใช้แสดงระหว่างสุ่มแล้ว
- แต่ละโฟลเดอร์มี `prompts.json` และ `runtime-assets.json`

เกมโหลด WebP ที่ลดขนาดสำหรับใช้งานจริง เก็บ alpha และสัดส่วนเดิม ภาพ UI รวมประมาณ 669 KB ภาพพิธีที่เป็นกลางพร้อมปุ่ม ? 620 KB และแสงว้าบ 229 KB โดยยังเก็บ PNG ต้นฉบับไว้ การเข้ารหัสซ้ำใช้ `scripts/encode-premium-ui.mjs` กับ sharp (ตั้ง `SHARP_MODULE` หากใช้ runtime ที่ติดตั้งแยกจากโปรเจกต์) ระบุชื่อโฟลเดอร์เป็น argument เพื่อเข้ารหัสเฉพาะชุดได้

พิธีมีลำดับรอเซิร์ฟเวอร์ → รวมแสง 900 ms → ผนึกคลาย 900 ms → พลังงาน/แสงว้าบ 620 ms → แสดงผนึกรางวัล สีบรรยากาศมาจากระดับสูงสุดของผลที่บันทึกแล้ว ภาพก่อนเปิดผลเป็นเพียงพลังงานไร้รูปร่าง ไม่มีรูปพระ สัตว์เลี้ยง หรือไอเท็มที่อาจทำให้เข้าใจผิดว่าได้รับสิ่งนั้น รางวัลที่เปิดจริงใช้รูปและระดับจากไอเท็มที่เซิร์ฟเวอร์ให้

ข้ามพิธี / ลดการเคลื่อนไหวจะเปิดให้ดูรางวัลทันทีและไม่แสดงแสงว้าบ ปิดหน้าต่างหรือสลับตู้จะเก็บผลชุดเดิมไว้ ไม่ส่งคำขอสุ่มใหม่ การเปิดรางวัลทีละชิ้นหรือทั้งหมดไม่คิดทองเพิ่ม
