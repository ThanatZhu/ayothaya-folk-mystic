# พระเครื่องส้ม แดง และรุ้ง · กรุเบญจภาคี

พระเครื่อง 5 แบบ แต่ละแบบมี 3 ระดับ คือ **ส้ม แดง และรุ้ง** รวม 15 ไอเท็ม มีวัตถุดิบร่วมในตู้ด้วย ใช้ช่อง `accessory` เดิม สวมใส่ได้พร้อมกันหนึ่งองค์ ทุกอาชีพ Lv.1 และตีบวกได้ถึง +20 ภาพเป็นพระพิมพ์นามธรรมตามภาพอ้างอิงของเจ้าของเกม ไม่มีรายละเอียดใบหน้าหรือพระพักตร์ กรอบทองเรียบ ลวดลายน้อย ชื่อและรูปทรงเป็นแรงบันดาลใจทางวัฒนธรรม ตัวเลขและความสามารถเป็นกลไกสมมติของเกม

| องค์ | บทบาท | เอฟเฟกต์หลัก |
| --- | --- | --- |
| พระสมเด็จวัดระฆัง | ป้องกัน | HP +100%, DEF +50%, ลดความเสียหาย 30% |
| พระรอดวัดมหาวัน | แคล้วคลาด | หลบหลีก +35 จุดเปอร์เซ็นต์, ความเร็วเคลื่อนที่ +15%, ลดความเสียหาย 20% |
| พระนางพญา | โจมตี | ATK/MATK +80%, คริติคอล +20 จุดเปอร์เซ็นต์, ตัวคูณดาเมจคริ +1.0, เจาะเกราะ 30% |
| พระผงสุพรรณ | ประหยัดทรัพยากร | HP +50%, ประหยัด MP 40%, ลดคูลดาวน์ 40% |
| พระกำแพงซุ้มกอ | ฟาร์ม | เบี้ยมอนสเตอร์ +200%, HP +30%, คริติคอล +15 จุดเปอร์เซ็นต์ |

ตารางด้านบนเป็น **เอฟเฟกต์พิเศษติดตัวเฉพาะรุ้ง** ระดับส้มมีสเตตัสพื้นฐาน 50% และระดับแดง 75% ของรุ้งองค์เดียวกัน แต่ไม่มีโบนัสเปอร์เซ็นต์หรือเอฟเฟกต์พิเศษ (`pct` และ `effect` ว่างทั้งคู่) เช่น ส้ม/แดงซุ้มกอมี LUK/DEX และ ATK/MATK ตามระดับ แต่ไม่เพิ่มเบี้ยจากมอนสเตอร์ ค่า STR/VIT ฯลฯ ยังมีผลตามสูตรสเตตัสทั่วไปของเกมตามปกติ

ภาพพระพิมพ์เดิมทุกระดับ พื้นไอคอนกับเงาเป็นส้มหรือแดงคงที่ ส่วนรุ้งใช้เงารุ้งเคลื่อนไหว `amuletAtTier` คำนวณทั้งตัวเลขและคำอธิบายจากข้อมูลเดียวกัน หน้าตู้มีปุ่มสลับดูทั้งสามระดับ โบนัสหลบหลีกเพิ่มเติมส่งผ่าน `fleeBonus` เข้าสูตรหลบการโจมตีมอนสเตอร์จริงด้วย

แต่ละองค์มีสเตตัสพื้นฐานเพิ่มเติม ดูตัวเลขจริงใน `amulets.js` โบนัสทำงานใน `deriveStats` ทั้งออนไลน์และออฟไลน์ ไม่มีโบนัสเพียงเพราะมีอยู่ในกระเป๋า สเตตัสคงที่ของชิ้นนั้นเพิ่มตาม Tier ตีบวกเดิม โบนัสเปอร์เซ็นต์ไม่คูณซ้ำตาม Tier และใช้เพดานรวมเดิม เช่น ลดความเสียหาย 30%, ลดคูลดาวน์ 40%, ความเร็วเคลื่อนที่ 15%, คริติคอล 50%

## ตู้กาชา

- อยู่ในเมนูสัตว์เลี้ยง → แท็บ **พระเครื่อง** ไม่มีปุ่มเพิ่มบน HUD
- 1 ครั้ง = 100 ทองแท่ง, 10 ครั้ง = 1,000 ทองแท่ง ใช้กระเป๋าทองแท่งเดิม ไม่เปิดช่องทางรับเงินจริงเพิ่ม
- รุ้งรวม **0.5%** แบ่งโอกาสเท่ากัน 5 องค์ = **0.1% ต่อองค์** สำหรับครั้งที่ไม่ใช่การันตี
- แดงรวม **4.5%** = **0.9% ต่อองค์**
- ส้มรวม **20%** = **4% ต่อองค์** ไม่มีพระระดับต่ำกว่าส้ม
- วัตถุดิบรวม **75%**: เหล็กไหล ×2 = 25%, ยันต์กันแตก ×1 = 20%, เศษวิญญาณบอส ×3 = 20%, ผลึกบอส ×1 = 10%
- ถ้าไม่ออกรุ้ง 99 ครั้ง ครั้งที่ 100 การันตีรุ้งหนึ่งองค์ (โอกาสเลือกแต่ละองค์ 20% ในครั้งการันตี) การได้รุ้งจากเรตปกติเริ่มนับการันตีใหม่
- ตัวนับแยกจากสัตว์เลี้ยง เก็บต่อเนื่องในตัวละคร ไม่รีเซ็ตเมื่อปิดหน้าต่างหรือออกเกม
- แต่ละครั้งได้รับพระหนึ่งองค์หรือวัตถุดิบหนึ่งรายการตามอัตราข้างต้น
- ของซ้ำเป็นไอเท็มหนึ่งชิ้นอีกครั้ง ไม่มีระบบดาวหรือแลกตัวซ้ำแฝง

## การบันทึก

`amuletDraw` ใช้ `id` ตรวจคำขอซ้ำและสุ่มด้วย `crypto.randomInt` ฝั่งเซิร์ฟเวอร์ ค่าเงิน ตัวนับการันตี receipt และไอเท็มบันทึกเป็น record เดียวผ่าน `persistMail` ก่อนส่ง `amuletChanged` กลับ หากกระเป๋าหรือกองไอเท็มเต็ม ยกเลิกทั้งชุดโดยไม่หักทอง หากบันทึกไม่แน่นอนจะตัดการเชื่อมต่อเพื่อโหลดสถานะที่บันทึกจริงใหม่ ไม่เดินหน้าด้วยกระเป๋าเงินเก่า

Receipt 64 คำขอล่าสุดอยู่ที่ `petCollection.amuletGacha.receipts` และไม่ส่งออกใน public snapshot การใช้ตู้สัตว์เลี้ยง การรับจดหมาย และการเปลี่ยนชื่อยังเก็บตัวนับนี้ไว้ การสุ่มสำเร็จระดับรุ้งประกาศในแชนเนลหนึ่งครั้งต่อรางวัล โดย retry ไม่ประกาศซ้ำ

## ภาพและพรีวิว

ภาพจริงอยู่ `assets/amulets-rainbow/*.png` สร้างด้วย built-in `image_gen` ตาม prompt ใน `docs/amulet-art-prompts.json` รุ่นที่มีลวดลายเยอะหรือเปลี่ยนเป็นตราเรขาคณิตไม่ได้ใช้ในเกม เงารุ้งใช้ `gear-rainbow` เดิมของกระเป๋า รวมถึงไอคอนและภาพหลักในหน้าตู้ และหยุดเคลื่อนไหวตาม reduced-motion

เปิด `amulet-gacha-lab.html` บน static server เพื่อทดลองด้วยทองสมมติ หน้านี้ใช้กฎสุ่มเดียวกัน แต่ไม่มีการเรียก API บัญชีผู้เล่น ปุ่มทดลองรุ้งมีเฉพาะห้องทดลอง ไม่ปรากฏในเกมจริง

ตรวจด้วย `node --test tests/amulet-gacha.test.mjs tests/amulet-host.test.mjs` และชุดทดสอบ pet / gear / stats / mailbox ที่เกี่ยวข้อง การเผยแพร่ต้องอัปเดตทั้งเว็บและ realm server (`/health` มี `amuletGacha:1`) ขณะนี้ไม่ได้เปิดรับชำระเงินจริง

## พิธีเปิดกรุ

จังหวะนำเสนอเหมือนตู้สัตว์เลี้ยง แต่ใช้หีบเขียวทองที่วาดใหม่: รอเซิร์ฟเวอร์ยืนยัน → รวมแสง 700 ms → หีบคลายผนึก 650 ms → หีบรางวัล 1/10 ใบลอยเข้ามา → แตะเปิดทีละใบหรือเปิดทั้งหมด → เสร็จสิ้นกลับหน้าตู้

การยืนยันคำขอเป็นจุดเดียวที่สุ่มและหักทอง การเปิดหีบ กดข้าม หรือเปิดทั้งหมดใช้เฉพาะ `amulet-ritual-state.js` ไม่เรียกเซิร์ฟเวอร์เพิ่ม ระดับรางวัลยึดข้อมูลจริงใน `itemDef` สีรุ้งมีแสงรุ้ง ส่วนส้ม แดง และวัตถุดิบแสดงสีของตัวเอง

ห้ามสุ่มชุดใหม่จนกว่าจะเปิดผลครบแล้วกดเสร็จสิ้น การปิดหน้าต่างหรือเปลี่ยนแท็บระหว่างพิธีจะข้ามช่วงนำเข้าไปเป็นหีบปิดที่พร้อมเปิด เก็บชุดเดิมไว้เมื่อกลับมา ของยังอยู่ในกระเป๋าแม้ออกจากเกมหรือโหลดหน้าใหม่แล้วไม่ได้ดูพิธีต่อ โหมด reduced-motion และตัวเลือกข้ามแอนิเมชันตัดการเคลื่อนไหวโดยไม่เปลี่ยนผลหรือเรต

ภาพหีบปิด/เปิด: `assets/amulet-ritual/closed.png` และ `open.png` สร้างด้วย built-in `image_gen` มี prompt และแหล่งภาพที่ `assets/amulet-ritual/prompts.json` ไม่มีการเปลี่ยนภาพพระพิมพ์เดิม

## Item-shaped rarity aura

All five amulet designs at rainbow/red/orange rarity use the existing transparent artwork. `iconStyle` keeps the image surface transparent; no colour fill or gradient is painted on the filtered image. Shadows therefore follow the item silhouette in bags, equipment, crafting, mail/trade displays and gacha rewards. The gacha catalogue images use the same grade helper. Orange and red gently pulse only shadow intensity; rainbow keeps the existing colour cycle. Item opacity and artwork colours remain constant, and reduced-motion preferences stop the animation.

Gacha result cards retain their normal jade surface, without rarity box shadows or a coloured card halo. The brief reveal flash is layered behind the item art. Browser validation compares all 15 variants before/after on transparent pixels, checks normal/reduced motion, and covers every catalogue preview and all three prize tiers at 1440×900, 844×390 and 390×844.
