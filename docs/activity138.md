# Quest / party dock and MVP bestiary — 138

The left HUD shares one live quest/party card. Tabs switch between the existing story tracker (including destination distance and the class trial journal) and the live party roster. Folding keeps the tabs available. The no-party view opens the existing invitation picker or channel roster; a party is formed when another player accepts, as before. Existing member targeting, invite permissions, full-party limits, leaving and leader management remain authoritative.

`activity-dock.js` measures the profile, wrapped buffs, events, chat and combat controls before placing the card. Touch layouts use a horizontal tab row and independently scrolling content. If no usable field space exists, an explicit tap opens a modal sheet. Background resize/buff updates collapse rather than automatically opening a modal. Moving the party DOM keeps it inside `game-shell`, where the multiplayer owner resolves its live elements. The former party and class-trial positioning owners yield when embedded.

The MVP menu is always available and opens a centered bestiary using the game's green/gold palette and existing font. MVP/world bosses and mini/awakened bosses have a selectable portrait list, a large portrait, stats, traits, spawn map, travel action and the actual drop definitions. Chapter-two portraits reuse the existing extracted art; legacy bosses are drawn from their original idle atlas frames. No substitute boss art or changed drop rules are introduced. The damage tab embeds the existing effective-damage results and five-encounter session history; defeating a boss still opens the result automatically.

`bossDirectory` is a read-only realm command, rate-limited to one accepted request per second; the browser polls every three seconds only while the catalog is open. Replies use the requesting player's realm/channel and existing MVP/map-boss clocks or live room mob state. Asking does not create or wake rooms. An unloaded mini-boss map has unknown status rather than a fabricated respawn time. Dungeon state is only read from the requesting player's own instance. The public health capability is `bossDirectory:1`.
