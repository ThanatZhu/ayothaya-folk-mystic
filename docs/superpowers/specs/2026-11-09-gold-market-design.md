# ทองแท่งในตลาดกลาง (ออกแบบ 9 พ.ย. 2026)

## ทำไม

ทองแท่งคือเงินพรีเมียมที่วันหนึ่งจะขายด้วยเงินจริง เจ้าของเกมอยากให้ทองแท่งไหลเวียนระหว่างผู้เล่นได้: วางขายของเป็นทองแท่งในตลาดกลาง และมีตลาดแลกเบี้ย ↔ ทองแท่งที่ราคาขึ้นลงตามผู้เล่น (แบบ Lost Ark / EVE) คนเติมเงินได้เบี้ยจากคนที่ฟาร์ม คนฟาร์มได้ทองแท่งไปเปิดกาชาหรือซื้อของในร้านโดยไม่ต้องเติมเงิน และหน้ากระแสเงินแสดงทองแท่งให้ทุกคนเห็น

## สิ่งที่เจ้าของเกมตัดสินแล้ว

- ตลาดกลางเดิมเพิ่มตัวเลือกว่าจะขายเป็น **เบี้ย** หรือ **ทองแท่ง**
- หน้าตลาดกลางมีหัวข้อใหม่ **แลกเบี้ย ↔ ทองแท่ง**
- กลไกราคา: **ผู้เล่นตั้งราคาเอง (กระดานซื้อขาย) + กรอบราคาต่อวันที่ระบบกำหนด** ไม่ใช่ระบบที่ตั้งราคาและเสกเงินเอง
- **ทำไว้รอ** เปิดใช้วันที่เปิดเติมเงินจริง
- **ล้างทองแท่งที่แจกไปแล้วทั้งหมดให้เหลือ 0 (แบบ ก)** ของที่ซื้อด้วยทองไปแล้ว (พระ สัตว์เลี้ยง ของจากร้าน) ผู้เล่นได้เก็บไว้ ก่อนล้างจริงต้องให้เจ้าของเห็นยอดก่อนแล้วยืนยันอีกครั้ง
- หน้ากระแสเงินเพิ่มส่วนทองแท่ง

## สิ่งที่ห้ามเกิด

- ระบบเสกเบี้ยหรือทองแท่งขึ้นมาเอง ทุกการซื้อขายต้องมีผู้เล่นอีกฝั่งจริง
- ทองหรือเบี้ยหายหรือเพิ่มขึ้นเพราะเน็ตหลุด กดซ้ำ หรือเซิร์ฟเวอร์รีสตาร์ทกลางรายการ
- ผู้เล่นโกงราคาได้จากฝั่งหน้าเว็บ (ราคา จำนวน ผู้ขาย ต้องเชื่อเฉพาะที่เซิร์ฟเวอร์)
- ผู้เล่นที่ไม่ได้ออนไลน์เสียของหรือเงินที่อยู่ในร้าน/คำสั่งซื้อขาย
- ระหว่างที่สวิตช์ปิด ผู้เล่นเห็นหรือใช้ส่วนทองแท่งในตลาดได้

## สภาพปัจจุบัน (ให้ผู้สร้างเข้าใจ)

- ทองแท่งอยู่ที่ `record.petCollection.balance` (ดู `pet-account.js`, `normalizePetAccount`) ใช้กับกาชาและร้านค้า (`premium-shop-action.js`) ตอนนี้ได้มาทางเดียวคือแอดมินส่งจดหมายแนบ `goldBars` (`admin.js` → `/admin/mail` → `mailbox.js` ตอนรับของ)
- ตลาดกลาง: `market-board.js` (กฎกลางที่หน้าเว็บกับเซิร์ฟเวอร์ใช้ร่วมกัน), `market-board-ui.js` (หน้าต่าง `#market-board` แท็บ สินค้าทั้งหมด / เปิดร้าน / ร้านของฉัน), ร้านถือของหรือเบี้ยไว้ใน escrow และเงินที่ขายได้รอใน `pouch` จนเจ้าของมาเก็บ มีภาษีตามเลเวลการค้า (`tradePerks`, `taxOf`) ราคาอ้างอิง (`recordPrice`, `priceHint`)
- ประมูล (`auction`) เป็นเบี้ยอย่างเดียว **ไม่อยู่ในงานนี้**
- หน้ากระแสเงิน: `explorer.html` + `explorer.js` อ่าน `/economy` จาก `server/economy-ledger.js` ยอดถือรวมคำนวณจาก `store.listProfiles` ทุก 6 ชม.
- แบบอย่างการแก้ข้อมูลผู้เล่นที่ออฟไลน์ทีละหน้าแบบทำซ้ำได้ปลอดภัย: `server/class-reward-backfill192.js` (cursor บันทึกทุกหน้า, `store.classRewardPage`, `giveOffline`)
- กติกาส่งงาน: release gate, server change ต้องขึ้นทั้ง `frontend-live` และ `main` (ดู `docs/unified-menu236.md` สำหรับหน้าต่าง)

## สิ่งที่จะสร้าง (แบ่ง 4 ช่วง ส่งทีละช่วงได้)

### ช่วง 1 · หน้ากระแสเงินแสดงทองแท่ง + รายงานก่อนล้างทอง

- `/economy` เพิ่ม `gold`: ทองแท่งที่ผู้เล่นถือรวม (ใน wallet), ทองที่ค้างอยู่ใน escrow ของร้านและคำสั่งแลก, จำนวนตัวละครที่ถือทอง, ทองแท่งเข้า/ออกรายวัน แยกที่มา (แจกจากแอดมิน, จดหมาย, เติมเงินในอนาคต) และที่ไป (กาชา, ร้านค้า, ภาษีตลาดทอง, การล้างทอง)
- ทองแท่งในจดหมายที่ยังไม่กดรับ นับแยกเป็นอีกบรรทัด
- ส่วนทองแท่งในหน้ากระแสเงินแสดงเสมอ (เปิดเผยได้แม้สวิตช์ตลาดปิด) พร้อมราคาแลกล่าสุดและกราฟราคาเมื่อช่วง 3 เปิดแล้ว

### ช่วง 2 · ล้างทองแท่งทั้งเซิร์ฟเวอร์ (ครั้งเดียว)

- หน้าแอดมินมีปุ่ม **ตรวจยอดก่อนล้าง** แสดง: จำนวนตัวละครที่ถือทอง ยอดทองรวม รายชื่อ 20 อันดับที่ถือมากสุด และทองในจดหมายที่ยังไม่รับ
- ปุ่ม **ล้างทองแท่ง** ใช้ได้หลังตรวจยอดแล้วเท่านั้น ต้องพิมพ์ยืนยัน ทำกับ: ทองใน wallet ทุกตัวละคร (ออนไลน์และออฟไลน์), ทองแท่งที่แนบในจดหมายที่ยังไม่กดรับ (เอาเฉพาะทองออก ของแนบอื่นยังอยู่)
- ทำซ้ำได้ปลอดภัย (รีสตาร์ทกลางทางแล้วทำต่อได้ ไม่ล้างซ้ำคนที่ได้ทองใหม่หลังล้างเสร็จ) ใช้แบบอย่าง class reward backfill
- บันทึกหลักฐาน (evidence) ทุกตัวละครที่ถูกล้าง: ชื่อ ยอดเดิม เวลา และบันทึกลงบัญชีทองแท่งเป็น "ล้างทอง"
- ของที่ซื้อด้วยทองไปแล้ว **ไม่แตะ**
- หลังล้าง หน้ากระแสเงินต้องแสดงยอดถือรวมเป็น 0

### ช่วง 3 · ตลาดกลางขายเป็นทองแท่ง

- ตอนเปิดร้าน (ทั้งร้านฝากขายและร้านรับซื้อ) เลือกสกุลเงินของร้าน: เบี้ย หรือ ทองแท่ง *(การตัดสินของผู้ออกแบบ: ทั้งร้านใช้สกุลเดียว ไม่ผสมรายชิ้น เพื่อให้ escrow และ pouch ง่าย)*
- ร้านรับซื้อแบบทองแท่ง: ทองแท่งของผู้เปิดร้านถูกกันไว้ใน escrow ตอนเปิด คืนเมื่อปิดร้าน
- เงินที่ขายได้เป็นทองแท่งรอใน pouch แยกช่อง (`pouch.gold`) เจ้าของกดเก็บเข้ากระเป๋าทอง
- ภาษีการขายเป็นทองแท่งใช้อัตราเดียวกับเบี้ย (`tradePerks().tax`) ทองภาษีหายออกจากเกม (บันทึกเป็นที่ไปของทองแท่ง) *(การตัดสินของผู้ออกแบบ)*
- ยอดขายเป็นทองแท่งไม่นับเป็นแต้มการค้า (trade XP) *(การตัดสินของผู้ออกแบบ: เลี่ยงการแปลงค่าเงิน)*
- หน้าค้นหา/รายการสินค้าแสดงไอคอนสกุลเงินชัดเจน กรองได้ว่า "ทั้งหมด / เบี้ย / ทองแท่ง" ราคาอ้างอิงเก็บแยกตามสกุล
- ร้านทองแท่งเปิดใหม่ไม่ได้ขณะสวิตช์ปิด ร้านที่เปิดอยู่ตอนสวิตช์ถูกปิดยังให้เจ้าของเก็บของและเงินคืนได้ แต่ไม่ให้ซื้อขายเพิ่ม

### ช่วง 4 · แลกเบี้ย ↔ ทองแท่ง (กระดานซื้อขาย)

**กติกา**
- สินค้าเดียว: ทองแท่ง 1 แท่ง ราคาเป็นเบี้ยต่อแท่ง
- คำสั่ง **ขาย** (ตั้งราคาขาย): ทองแท่งถูกกันใน escrow ทันที คำสั่ง **ซื้อ** (ตั้งราคารับซื้อ): เบี้ยเต็มจำนวน (ราคา × จำนวน) ถูกกันใน escrow ทันที
- จับคู่อัตโนมัติ: ราคาดีที่สุดก่อน ถ้าราคาเท่ากันใครตั้งก่อนได้ก่อน ซื้อขายกันที่ราคาของคำสั่งที่ตั้งรออยู่ก่อน ถ้าซื้อได้ถูกกว่าที่กันเบี้ยไว้ ส่วนต่างคืนผู้ซื้อ
- **ซื้อทันที / ขายทันที**: กินคำสั่งที่ดีที่สุดที่มีอยู่จนครบจำนวนหรือจนหมดกรอบราคา ส่วนที่เหลือไม่ตั้งรอ (บอกผู้เล่นว่าได้กี่แท่ง)
- จับคู่ได้แม้อีกฝั่งออฟไลน์ เงิน/ทองที่ได้รอใน "กระเป๋าตลาดแลก" ของคนนั้นจนเข้ามากดรับ *(หรือเข้ากระเป๋าตรงถ้าทำได้อย่างปลอดภัย ให้ผู้สร้างเลือก)*
- **กรอบราคาต่อวัน**: ราคาอ้างอิงของวัน = ราคาปิดของวันก่อน (ซื้อขายจริงครั้งสุดท้ายของวันไทย) ตั้งราคาได้ในช่วง ±20% ของราคาอ้างอิงเท่านั้น วันแรกใช้ราคาเริ่มต้นที่แอดมินตั้ง (ค่าเริ่มต้นเสนอ 500 เบี้ย/แท่ง ให้เจ้าของเปลี่ยนได้ในหน้าแอดมิน) วันไหนไม่มีการซื้อขาย ราคาอ้างอิงคงเดิม
- **ค่าธรรมเนียม 5%** หักจากเบี้ยที่ผู้ขายทองได้รับ เบี้ยนี้หายออกจากเกม (บันทึกในบัญชีเบี้ยเป็น "ค่าธรรมเนียมแลกทอง") *(ค่าเสนอ เจ้าของเปลี่ยนได้)*
- คำสั่งค้างได้นานสุด 7 วัน หมดอายุแล้วคืน escrow อัตโนมัติ ยกเลิกเองได้ตลอด (ส่วนที่ยังไม่จับคู่)
- จำกัดต่อตัวละคร: คำสั่งเปิดพร้อมกันไม่เกิน 10, จำนวนต่อคำสั่ง 1–10,000 แท่ง
- ทุกการซื้อขายบันทึกหลักฐาน และนับเข้าราคาย้อนหลังรายวัน (เปิด ปิด สูง ต่ำ ปริมาณ)

**หน้าตา** (หัวข้อใหม่ในหน้าต่างตลาดกลาง ใช้กรอบ 236 ตามกฎ)
- ราคาล่าสุด การเปลี่ยนแปลงวันนี้ กรอบราคาวันนี้ ปริมาณ 24 ชม.
- กระดาน: ราคาขายถูกสุด 5 ระดับ และราคารับซื้อสูงสุด 5 ระดับ พร้อมจำนวน
- ฟอร์ม: แท็บ ซื้อ/ขาย, จำนวน, ปุ่ม "ซื้อทันที/ขายทันที" (แสดงราคาเฉลี่ยโดยประมาณและยอดรวม) และ "ตั้งราคาเอง"
- คำสั่งของฉัน (ยกเลิกได้) และประวัติการซื้อขายของฉัน
- กราฟราคา 7/30 วัน (ใช้รูปแบบเดียวกับหน้ากระแสเงิน)

**แยกตามเซิร์ฟเวอร์** *(การตัดสินของผู้ออกแบบ)*: ตัวละครอยู่เซิร์ฟเวอร์เดียว และร้าน ราคาอ้างอิง ประมูล ก็แยกตาม `serverId` อยู่แล้ว กระดานแลก ราคาอ้างอิง กรอบราคา และราคาย้อนหลังจึงแยกต่อเซิร์ฟเวอร์ (เบี้ยของสองเซิร์ฟเวอร์ไม่ข้ามกัน) ส่วนสวิตช์และราคาเริ่มต้นมีชุดเดียวใช้ทุกเซิร์ฟเวอร์ หน้ากระแสเงินแสดงราคาของแต่ละเซิร์ฟเวอร์

**คำสั่งที่หลุดกรอบราคาของวันใหม่** *(การตัดสินของผู้ออกแบบ)*: ยังค้างอยู่ แต่จับคู่ไม่ได้จนกว่ากรอบจะกลับมาครอบราคานั้น และยังหมดอายุตาม 7 วันเดิม หน้าเว็บแสดงว่า "นอกกรอบราคาวันนี้" ผู้เล่นยกเลิกเองได้ ราคาเริ่มต้นในหน้าแอดมินแก้ได้เฉพาะก่อนมีการซื้อขายครั้งแรกของเซิร์ฟเวอร์นั้น

### สวิตช์เปิด/ปิด

- หน้าแอดมินมีสวิตช์ **ทองแท่งในตลาด** (ครอบช่วง 3 และ 4) ค่าเริ่มต้น **ปิด** เก็บไว้ฝั่งเซิร์ฟเวอร์ รอดรีสตาร์ท
- **ต้องล้างทอง (ช่วง 2) เสร็จก่อน** เซิร์ฟเวอร์จึงยอมให้เปิดสวิตช์ *(การตัดสินของผู้ออกแบบ)* ทำให้ตอนล้าง ทองมีอยู่แค่ใน wallet กับจดหมายที่ยังไม่รับ ไม่ต้องตามล้างใน escrow ร้าน pouch หรือคำสั่งแลก ลำดับส่งงานจึงเป็น 1 → 2 → 3 → 4
- ปิดอยู่: หน้าเว็บซ่อนแท็บแลกทองและตัวเลือกร้านทองแท่ง เซิร์ฟเวอร์ปฏิเสธคำสั่งที่เกี่ยวกับทองทั้งหมด (ยกเว้นยกเลิก/เก็บคืน)
- ระหว่างทดสอบในเครื่อง (`AUTH_MODE=local`) เปิดได้

## ปล่อยให้ผู้สร้างตัดสิน

- รูปแบบข้อมูลและที่เก็บของกระดานแลก (แยกไฟล์/คอลเลกชันแบบร้านค้า หรือรวมกับตลาด)
- วิธีส่งเงินให้ผู้ที่ออฟไลน์ (กระเป๋าตลาดแลก หรือ giveOffline) ตราบที่ไม่มีอะไรหายหรือซ้ำ
- การจำกัดความถี่คำสั่ง (rate limit) ใช้แบบเดียวกับคำสั่งอื่นในเซิร์ฟเวอร์
- ข้อความภาษาไทยและคำแปลอังกฤษ (`i18n-en.js`)
- รูปแบบกราฟและการจัดหน้าบนมือถือ ตามหน้าตาเดิมของตลาดกลางและกฎกรอบ 236

## ตรวจรับ

- เทสกฎกลาง: escrow ไม่หาย ไม่ซ้ำ, จับคู่ถูกลำดับ, กรอบราคา, ค่าธรรมเนียม, หมดอายุ, ยกเลิก, กดซ้ำด้วย request id เดิม, กระเป๋าเต็ม, ออฟไลน์
- เทสล้างทอง: ทำซ้ำได้, ไม่ล้างทองที่ได้หลังล้าง, จดหมายที่ยังไม่รับ
- รันเกมในเครื่องกับสองตัวละครจริง: ขายของเป็นทอง, แลกทองทั้งสองทาง, สวิตช์ปิดแล้วใช้ไม่ได้
- `npm run release:check` ผ่าน
