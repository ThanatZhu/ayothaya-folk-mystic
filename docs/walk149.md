# Persistent destination walking and unobstructed coach — 149

Opening a menu, modal, map or inventory, changing focus and hiding the page now clear only held buttons/touches. They no longer cancel a destination. WASD, joystick steering or an explicit cancellation/replacement route cancel the old route. Destination input is separate from held movement, so the existing 350 ms manual-input timeout still prevents stuck keys.

For online play the client sends a destination request and the authority validates it against the current map/nav, plans around obstacles and simulates the route at normal movement speed. NPC and monster references resolve on the server. Snapshots include the route ID and walking/arrived/failed/cancelled state. Client prediction still follows a local route, but arrival callbacks wait for authoritative arrival; when a blocking menu or hidden page is present they run once the UI is available again. Neither menus nor a suspended browser frame loop need to keep sending steering packets.

When a connection drops mid-route the host holds its existing account lease and continues the normal world simulation, including damage and collision, until arrival/failure. It checkpoints progress and releases the lease after completion. A reconnect saves/releases the old lease first and resumes the same authoritative peer/route. Background jobs are bounded by token expiry and a 10-minute session limit. Explicit leave/travel/class-change follows the existing save/release flow. Route destinations are saved only in the private profile and are not imported from or written to the client mirror. Death or an unreachable path still fails normally.

Pages restored from the browser back/forward cache reconnect when necessary. Arrival interactions/UI callbacks are delayed while the page is hidden or a blocking menu is open. Cross-map quest transitions retain the existing UI travel flow; a suspended page resumes that transition when active again.

Coach placement measures the real bubble height and tries clear positions beside/below/above the quest panel. It avoids the target and visible controls. With no clear space, only the pointer-events:none ring/arrow remains. Layout work is cached until target/viewport/panel geometry changes.
