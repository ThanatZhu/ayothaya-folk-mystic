# Browsable central market

Opening the central market requests listings immediately. The default view shows every active selling shop and online stall in the current server, ordered by listing creation time. Twenty-four offers appear per page, with a server-calculated total and pagination; the old 40-result search ceiling does not apply to browsing. Category, seller/shop/item text search, buy/sell shop type, unit-price range and sorting combine on the server.

Desktop keeps search/filter controls and pagination fixed around a scrolling two-column product grid. The right column shows market totals and popular purchases. Mobile collapses extra filters and popularity into expandable sections to expose products immediately, with a compact scrolling grid on short landscape screens. Existing generated jade/gold frames, buttons and item images remain in use. No raster artwork is needed for live text or filter controls.

Popularity counts completed shop purchases, fulfilled buying orders and online-stall purchases, by units and transactions, for the current Bangkok calendar day. Equipment variants share their base item. Bounded seven-day aggregates extend the existing persisted price records; legacy averages and shop logs are not fabricated into historical counts. New counts begin when this backend version is installed, and remain after sellers collect or delete their shops. No buyer identities or private shop proceeds enter browsing responses.

The client subscribes only while browsing. Shop mutations mark the server dirty; a once-per-second sweep detects live-stall changes, disconnects and daily rollover. Only subscribed players receive changed pages, not idle broadcasts or client polling. Closing the panel or leaving the browse tab unsubscribes. Responses have request IDs so earlier searches cannot overwrite later input; live updates preserve focus, caret and list scroll. Sold-out, closed and expired listings remain excluded by the existing 24-hour shop rules.

Frontend and realm server must both be updated. The release cache chain is `game.html` → `game-boot.js?v=market191` → `viewer-world.js?v=market191`; the market module and CSS use `market188`. Backend health advertises `marketBrowse:1` and `marketDemand:1`. Existing purchase, proximity, escrow, tax and collection rules remain unchanged. The final integration also retains `598d431`'s quest tracker scroll and its module cache keys.

Validation: `tests/market188.test.mjs`, existing market/shop lifecycle suites and translations. `scripts/check-market188.mjs <Playwright module path>` starts an isolated local host with 192 fixture offers, checks opening without search, filtering, pagination, a real WebSocket purchase, live updates/unsubscription and desktop/mobile Thai/English layouts. Screenshots and private fixtures stay under untracked `outputs/market188/`.
