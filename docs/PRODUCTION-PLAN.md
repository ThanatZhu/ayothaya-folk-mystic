# แผนผลิตและรายการงาน

Phase 1 จัดทำแล้วในเอกสาร/ข้อมูลชุดนี้ ส่วน Phase 2–10 เป็นงานรอทำ ไม่ได้ถือว่าจบเพราะระบบต้นแบบมีชื่อหรือหน้าตาใกล้เคียงกัน

| Phase | ส่งมอบ | ต้องมีก่อน | เกณฑ์ตรวจรับ |
|---|---|---|---|
| 1 | GAME-DESIGN, ASSET-SPEC, chapter-01 และ validator | ตรวจฐานเกม 0.15 | reference ถูกต้อง เควสต์ไม่มีวงวน EXP/เงินคำนวณได้ แยกของจริงกับของวางแผน |
| 2 | สไปรต์และ animation controller หลายทิศ | ข้อกำหนดภาพ | หมอผีชาย/หญิงผ่านก่อน แล้วจึงครบทุกอาชีพ; รูปลักษณ์ไม่หลุดตำแหน่ง |
| 3 | EXP/สถานะ/สกิล/AI/บอส | domain state และ action events | ทุกอาชีพปราบบอสได้ ท่ากับ damage ตรงกัน มีตาราง EXP รองรับเซฟเก่า |
| 4 | กระเป๋า เงิน อุปกรณ์ ดรอป ร้านค้า คราฟต์ | schema และ reward service | ซื้อ/ขาย/ใส่/คราฟต์ครบ ราคาและจำนวนไม่ติดลบ retry ไม่ให้ของซ้ำ |
| 5 | บทแรกและสมุดเควสต์ | objective events จาก Phase 3–4 | จบ 10 เควสต์ครบทุกอาชีพ เงื่อนไขไม่ติดวงวน |
| 6 | เซฟ schema ใหม่ + migration + เน็ตหลุด | ข้อมูลใหม่ทุกระบบ | บัญชีจริงสองอุปกรณ์โหลดตรงกัน มีสำรองและ conflict recovery |
| 7 | authoritative multiplayer, rooms, party, chat | service adapter ที่แยกจาก UI | clients สองรายเห็นผลเดียวกัน เซิร์ฟเวอร์ตรวจเงิน/ไอเทม/รางวัล |
| 8 | กิจกรรมทุกเมือง ดันเจียนและสายอาชีพเพิ่ม | บทแรกเล่นสนุกและระบบเสถียร | ทุกเมืองมีบริการ เป้าหมาย และเส้นทางเลเวลชัดเจน |
| 9 | เสียง สมดุล UX ประสิทธิภาพ และ Closed Beta | gameplay และ save เสถียร | แก้บั๊กสำคัญจากผู้เล่นจริง ผ่าน Android/iPhone และ load test |
| 10 | เครื่องมือดูแล สำรอง กู้คืน รายงานปัญหา และเปิดรุ่นแรก | ผล Beta | ทดลองกู้คืนได้จริง มีขั้นตอน rollback และเฝ้าดูข้อผิดพลาด |

- [ ] A02 เดิน 8 เฟรมและ idle 4 เฟรมต่อทิศ ตรวจ contact/pass/น้ำหนัก และการเปลี่ยนทิศ

- [ ] A04 แยกชั้นเครื่องแต่งกาย; ทดลองผม ชุด และอาวุธพร้อมกันในทุกทิศ
- [ ] A05 แทนตัวควบคุมภาพเดิมด้วยคลิปใหม่ มี fallback จนทุกอาชีพครบ ไม่ถอดภาพเดิมก่อนผ่าน
- [ ] S01 กำหนด schema 2, migration fixtures และ service adapter ก่อนเขียนระบบรางวัล
- [ ] C01 EXP สะสม/เลเวล/ค่าสถานะ แยกจาก kills; ตรวจ migration ผู้เล่นเดิมทุกระดับ
- [ ] C02 action lifecycle + damage events + AI คำเตือนบอส; ตรวจหลบได้ทุกอาชีพ
- [ ] I01 inventory/stack/equip/wallet และตรวจ ownership/revision
- [ ] I02 drop, buy, sell, craft และ transaction แบบ idempotent
- [ ] Q01 quest state machine: locked → available → active → ready → claimed; objective events แยกจากข้อความ
- [ ] Q02 เชื่อม NPC 6 คนและเควสต์ 10 ตอน เพิ่มดันเจียนกับทางออก; เนื้อหาทั้งหมดใช้ stable IDs
- [ ] Q03 เควสต์อาชีพขั้น 2 และ grandfather เซฟเก่าที่ปลดล็อกแล้ว
- [ ] S02 เขียนการเซฟทุก state ใหม่ทันทีที่สร้างแต่ละระบบ ไม่เลื่อนไปรวมทีเดียวตอน Phase 6
- [ ] S03 ทดสอบ Google จริงข้ามเครื่อง/สองแท็บ/offline/reconnect และ transaction ที่สำเร็จแต่คำตอบหาย
- [ ] V01 เล่นบทแรกตั้งแต่สร้างตัวละครถึงรายงานบอสครบ 7 อาชีพ และบันทึกเวลาจริง

## สิ่งที่ต้องรักษา

- Google UID + server ID เป็นขอบเขตข้อมูลเสมอ; guest ไม่ทับ cloud และ server 1 ไม่ทับ server 2
- ห้ามนำ chapter-01 ไปเปลี่ยนแมพจริงโดยตรงจนมี runtime quest service และ migration ที่ทดสอบแล้ว
- ค่า 31 นาที, จำนวนช่องกระเป๋า และค่า EXP เป็นค่าเริ่มต้นสำหรับทดสอบ ปรับจากการเล่นจริงได้
- ทุกเฟสจบด้วยรายการสิ่งที่ใช้งานได้ ผลทดสอบ และข้อจำกัด ไม่เรียกว่าพร้อมเปิด MMO จนเซิร์ฟเวอร์ควบคุมผลเกมจริง
- ไม่มีการเปิดระบบซื้อขายระหว่างผู้เล่นก่อน authority ของไอเทม/เงินอยู่บนเซิร์ฟเวอร์

## ตรวจข้อมูล Phase 1

รัน `npm run check:content` ตรวจชื่อและ ID อ้างอิงกับแมพจริง กราฟเควสต์ จำนวนของ/เงิน/EXP และเงื่อนไขปลดล็อก รายการข้อมูลบทแรกยังไม่ถูกโหลดในเกม และ build เว็บไซต์ไม่จำเป็นต้องรวมไฟล์ออกแบบเหล่านี้
